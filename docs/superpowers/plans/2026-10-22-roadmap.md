## 1. كيف تُستخدم هذه الخريطة

الوثيقة تحدد ترتيب المراحل، ومحتوى كل مرحلة، ومعايير الخروج منها، دون أن تسبق التنفيذ بتوقيعات تخمينية.

القاعدة:

- كل مرحلة تحصل على خطة تنفيذ تفصيلية خاصة بها قبل كتابة كودها.
- تُكتب خطة المرحلة التالية بعد نجاح بوابة المرحلة الحالية، لا قبلها.
- الاستثناء هو المرحلة 0، وخطتها مكتوبة الآن لأن كل المراحل تعتمد على واجهاتها.
- أي قرار جديد يغيّر التصميم يُحدّث في وثيقة التصميم أولًا، ثم في خطة المرحلة.

سبب هذا التقسيم:

- توقيعات المراحل اللاحقة تعتمد على كود عامل، لا على تصور.
- خطة واحدة لكل المراحل ستكون مليئة بتفاصيل ستتغير، وهذا يخالف مبدأ الخطة القابلة للتنفيذ.

## 4. المرحلة 1: الأمان والإشراف واللوقات

**الهدف:** جعل السيرفر محميًا قبل إضافة أي ميزة مجتمعية. هذه المرحلة هي جوهر طلب المستخدم: نظام وحماية.

**الخطة:** `docs/superpowers/plans/YYYY-MM-DD-01-security.md` (تُكتب عند البدء).

**قائمة المهام المقترحة:**

1. مخطط إعدادات الأمان، القيم الافتراضية، خدمة إعدادات مع تدقيق واختبارات.
2. جامع أحداث Anti-Nuke، قراءة Audit Log، التجميع الزمني، العتبات، القائمة البيضاء، ووضع Dry Run.
3. لقطات القنوات والرتب، وإعادة الإنشاء حيث يمكن، مع توثيق ما لا يمكن استعادته.
4. بوابة Anti-Raid: معدل الانضمام، عمر الحساب، الحجر الصحي، وضع الريد، والإيقاف التلقائي.
5. لوحة التحقق: زر، Modal، سؤال رياضي أو صورة تحقق، ودور بعد النجاح.
6. محرك Automod: سبام، روابط، دعوات، أحرف كبيرة، ذكر جماعي، كلمات ممنوعة، زالغو، مرفقات، استبعادات، ونقاط تصعيد.
7. خدمة حالات الإشراف: حظر، حظر مؤقت، طرد، كتم، إنذار، ملاحظة، مسح، قفل، بطء، وكنية، مع فحص تسلسل الرتب.
8. خدمة اللوقات: أحداث الأعضاء والرسائل والقنوات والرتب والصوت والدعوات، تنقية الأسرار، وتجميع الأحداث.
9. أوامر `/security`, `/automod`, `/verification`, `/logs` وأوامر الإشراف، مع تأكيدات واختبارات صلاحيات.
10. الطوارئ: `/security raidmode`, `/security lockdown`، وتوسيع `/doctor` بفحص صلاحيات الحماية.
11. تدريب يدوي: ريد وهمي، نيوكن وهمي، سبام، ورابط سكام، مع مراجعة سجل التدقيق.
12. مراجعة أمنية للمرحلة، تحديث التوثيق، وبوابة الخروج.

**معيار الخروج:**

- سيناريو ريد وهمي يُحتوى تلقائيًا أو يدويًا وفق الإعداد.
- سيناريو نيوكن وهمي يُسجّل الفاعل ويعاقبه، أو يوقفه في Dry Run.
- Automod يمنع الحالات الإيجابية ولا يعاقب الحالات السلبية في مجموعة الاختبار.
- كل إجراء إشرافي له حالة مرقمة وسجل تدقيق.
- لا توكن أو سر في أي سجل.
- اختبارات مصفوفة الصلاحيات خضراء.
- `npm run check` أخضر.

**المخاطر:**

- تأخر Audit Log قد يسبب فاعلًا مجهولًا. يُعالج بإعادة المحاولة، وتنبيه بدل إجراء أعمى، وتوثيق الخطر المتبقي.
- العتبات قد تسبب إيجابيات كاذبة. يُعالج بـ Dry Run افتراضي وقائمة بيضاء.
- لقطات القنوات لا تستعيد الرسائل. يُوثّق بوضوح.

**الهدف:** بناء تفاعل الأعضاء: ترحيب، رتب، مستويات، اقتصاد، سحوبات، واقتراحات.

**الخطة:** `docs/superpowers/plans/YYYY-MM-DD-02-community.md`.

**قائمة المهام المقترحة:**

1. ملف العضو، خدمة XP والمستوى، مهل الرسائل، ومكافآت الرتب.
2. اختبار مبكر لتشكيل العربية في بطاقة الرتب، مع بديل Embed نصي إذا فشل التشكيل.
3. حساب الاقتصاد وسجل المعاملات، مع ثوابت الرصيد غير السالب والمعاملات الذرية.
4. المتجر والمخزون والتجارة، مع تأكيدات وحدود.
5. أوامر الكسب: daily, work, crime, fish, mine, rob, gamble، مع مهل وحدود.
6. الترحيب والوداع والرتب التلقائية.
7. قوائم الرتب بالأزرار والقوائم المنسدلة، والرتب الذاتية.
8. السحوبات: إنشاء، اشتراك، إنهاء، إعادة سحب، متطلبات، وجدولة.
9. أعياد الميلاد، الاقتراحات، Starboard، Counting، Rep، AFK، Tags، الدعوات، Temp Voice، والعدادات (تُقسم على 2-3 مهام).

11. اختبار إعادة تشغيل المجدول، ومنع تكرار المهام، واستمرار السحوبات.
12. بوابة المرحلة.

**معيار الخروج:**

- سجل الاقتصاد متوازن في كل اختبار، ولا رصيد سالب.
- السحوبات تُغلق في وقتها وتنجو من إعادة التشغيل.
- XP له مهل وحدود ولا يُمنح في القنوات المستبعدة.
- بطاقة الرتب تعرض العربية بشكل صحيح، أو يوجد بديل نصي موثّق.
- كل أمر مجتمعي له إعداد، صلاحية، اختبار، وسجل تدقيق عند الحاجة.
- `npm run check` أخضر.

**المخاطر:**

- تشكيل العربية في Canvas قد يفشل. البديل: Embed نصي، أو مكتبة Pango.
- التضخم الاقتصادي. يُعالج بحدود، مهل، وعمر حساب.
- تعقيد قوائم الرتب. يُعالج بحد 25 خيارًا ورسائل متعددة.

## 6. المرحلة 3: التذاكر وModmail والتقديمات

**الهدف:** نظام دعم كامل: تذاكر، رسائل خاصة، ونماذج تقديم.

**الخطة:** `docs/superpowers/plans/YYYY-MM-DD-03-tickets.md`.

**قائمة المهام المقترحة:**

1. مخطط التذاكر والإعدادات ولوحة الفتح والإغلاق والصلاحيات.
2. الاستلام، الأولوية، الإضافة والإزالة، النسخة، التقييم، والحدود.
3. مولّد نسخة HTML مع تهريب آمن، مرفقات، ومدة احتفاظ.
4. القائمة السوداء وإحصاءات الموظفين.
5. Modmail: خيوط، رسائل، مرفقات، ملاحظات داخلية، وإغلاق.
6. التقديمات: تعريف نموذج، إرسال، مراجعة، قبول أو رفض.
7. أوامر `/ticket`, `/modmail`, `/apply` وi18n والصلاحيات.
8. تضمين النسخ في النسخ الاحتياطي، واختبار استعادة.
9. بوابة المرحلة.

**معيار الخروج:**

- دورة تذكرة كاملة: فتح، استلام، إضافة، إغلاق، نسخة، تقييم.
- لا يمكن لعضو عادي رؤية تذكرة غيره.
- نسخة التذكرة تهرب HTML وتمنع XSS.
- Modmail يمرّر الرسائل في الاتجاهين ويدعم الملاحظات الداخلية.
- التقديم يُخزّن ويُراجع ويُقبل أو يُرفض.
- النسخة الاحتياطية تستعيد قاعدة البيانات والنسخ معًا.
- `npm run check` أخضر.

**المخاطر:**

- تسريب تذاكر بسبب Overwrites خاطئة. تُختبر مصفوفة الصلاحيات.
- تخزين محتوى خاص. يُوثّق في سياسة الخصوصية ويُحدد الاحتفاظ.
- مرفقات كبيرة. تُحدد الأحجام والأنواع.

## 8. المرحلة 5: لوحة التحكم المحلية

**الهدف:** واجهة ويب محلية لإدارة الإعدادات والسجلات والتذاكر.

**الخطة:** `docs/superpowers/plans/YYYY-MM-DD-05-dashboard.md`.

**قائمة المهام المقترحة:**

1. خادم Fastify، فحص صحة، رؤوس أمان، وربط افتراضي بـ `127.0.0.1`.
2. OAuth2، جلسات SQLite، CSRF، RBAC، وحد معدل.
3. نظرة عامة، إعدادات، وإصدار إعدادات لمنع التعارض.
4. صفحات الأمان وAutomod.
5. صفحات اللوقات والحالات والتذاكر والنسخ.
6. صفحات الاقتصاد والمستويات والسحوبات والنسخ الاحتياطي.
7. اختبارات XSS وCSRF والصلاحيات وRTL.
8. بوابة المرحلة.

**معيار الخروج:**

- المالك يسجّل الدخول ويعدّل إعدادًا، وينعكس فورًا في البوت.

- لا يظهر التوكن في أي صفحة أو استجابة.

**المخاطر:**

- كشف اللوحة للإنترنت دون TLS. تُربط محليًا، والوصول البعيد مرحلة لاحقة.
- XSS عبر محتوى المستخدم. يُهرب كل شيء، وتُختبر الحالات.
- تعارض الكتابة. يُعالج بإصدار الإعدادات.

## 10. المرحلة 7: التقوية النهائية

**الهدف:** إثبات أن النظام يصمد، وتوثيق التشغيل، وتجهيز النشر.

**الخطة:** `docs/superpowers/plans/YYYY-MM-DD-07-hardening.md`.

**قائمة المهام المقترحة:**

1. اختبار تحميل 1000 رسالة/دقيقة لمدة ساعة، وقياس الذاكرة وزمن الاستجابة.
2. اختبار استعادة نسخة احتياطية كامل، مع نسخ التذاكر.
3. مراجعة أمنية نهائية و`npm audit`.
4. سكربتات النشر: PM2 أو NSSM على Windows، وDocker Compose على Linux.
5. توثيق التثبيت والتشغيل والصيانة واستكشاف الأخطاء.
6. اختبار دخان نهائي وقائمة قبول.
7. وسم الإصدار الأول.

**معيار الخروج:**

- 24 ساعة تشغيل مستقر بلا انهيار.
- الذاكرة مستقرة بلا تسريب ملحوظ.
- استعادة النسخة مُثبتة.
- لا ثغرات عالية غير مبررة.
- التوثيق يغطي التثبيت والتشغيل والنسخ والاستعادة.
- `npm run check` و`npm run build` أخضران.

## 11. بوابات الجودة لكل مرحلة

كل مرحلة، دون استثناء:

- خطة تفصيلية مكتوبة ومراجعة قبل الكود.
- اختبارات أولًا للمنطق القابل للاختبار.
- `npm run check` أخضر: نوع، lint، اختبارات، إيموجي، i18n.
- فحص i18n: لا مفاتيح ناقصة، ولا إيموجي.
- اختبارات صلاحيات لكل أمر حساس.
- سجل تدقيق لكل عملية إدارية أو مالية.
- نسخة احتياطية قبل أي ترحيل.
- تحديث التوثيق.
- اختبار يدوي في سيرفر تجريبي.
- لا سر في git أو السجلات.
- لا تبعية جديدة دون مبرر وفحص رخصة.
- عدد الأوامر العلوية أقل من 90.
- commit مستقل لكل مهمة.

| 1 | 25 | 30 |

| 4 | 1 | 51 |
| 5 | 0 | 51 |
| 6 | 27 أساسي + 3 اختياري | 81 |
| 7 | 0 | 81 |

قاعدة: إذا وصل المجموع إلى 85، تُدمج الأوامر في مجموعات قبل إضافة أي أمر جديد.

## 13. قائمة كتابة أي خطة مرحلة

قبل كتابة خطة أي مرحلة:

1. أعد قراءة أقسام وثيقة التصميم المتعلقة بها.
2. حدد الملفات والواجهات الدقيقة بناءً على الكود العامل، لا على التخمين.
3. اكتب 10-14 مهمة، كل مهمة قابلة للاختبار وحدها.
4. ابدأ كل مهمة باختبار فاشل عندما يكون المنطق قابلًا للاختبار.
5. ضمّن اختبارات الحالات الحدية الخمس الأخطر.
6. حدد معيار خروج قابلًا للقياس.
7. حدّث وثيقة التصميم إذا تغير قرار.
8. اعرض الخطة على المستخدم قبل التنفيذ.

## 14. الوضع الحالي والخطوة التالية

- وثيقة التصميم معتمدة.
- خطة المرحلة 0 مكتوبة وجاهزة للمراجعة.
- لا كود منتج مكتوب بعد.
- لا Node أو Git مثبتان بعد.

الخطوة التالية:

1. مراجعة خطة المرحلة 0.
2. اختيار طريقة التنفيذ: Subagent-driven أو Native.
3. تنفيذ المرحلة 0 والتحقق من بوابتها.
4. كتابة خطة المرحلة 1 بعد نجاح المرحلة 0.
5. تكرار ذلك حتى المرحلة 7.
